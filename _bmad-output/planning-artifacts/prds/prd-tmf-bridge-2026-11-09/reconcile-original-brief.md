# Reconcile: Original Brief vs PRD (2026-11-09)

Scope: gaps only. Excluded as decided: re-tiering per addendum, drift/GitOps out, expression language deferred, throughput/availability NFRs dropped, success measures deferred, open items dropped, saga/retry/async/hub Later, listed FRs S1.

## Top gaps

1. **Error handling and "nothing internal leaks" has no requirement.** Brief FR-17, AC8 and the voice ("past vendor leaked Oracle stack traces to a partner") ask for backend 404/SOAP faults/validation failures to become TMF Error + HTTP status by config, with no internal detail. The PRD only has this as a UJ-2 clause ("leaks no legacy internals") and FR-15 (log redaction). No FR covers response-side error mapping, 400/422 business validation, or sanitised faults. FR-2 covers only 501.
2. **Safe, governed publishing is gone.** Brief FR-19/20/21, AC11: draft/validate/test/publish, invalid mapping unpublishable, dry-run against a draft with each backend call shown and NO side effects on real backends, roles viewer/author/publisher, audit trail of every change. PRD FR-11 is just "apply"; FR-10 "test a call" has no no-side-effects guarantee and no per-backend-call view. No validation gate, roles or audit trail, and these are not listed under Later (only history/diff/rollback is).
3. **Honesty/transparency qualities silently dropped.** "Filtering fallback must be honest: say so in response headers" (brief FR-09, scenario 2) has no trace, since query delegation is Later but the honest-headers principle is not carried. Likewise "Consumers see ODA; legacy untouched", correct X-Total-Count/X-Result-Count, and "acknowledged fast, follow async" are not preserved as design principles for the Later items.
4. **Capabilities in neither S1, Later, nor Out of Scope (orphaned).** TMF642 entirely (alarms, tasks, Kafka events, ack/clear), TMF622 writes (create, PATCH merge-patch, delete, cancelProductOrder, state lifecycle), generated TMF conventions (id, href, lifecycleStatus, validFor, lastUpdate; brief FR-06), southbound protocol set (REST, SOAP, read-only SQL, Kafka, webhooks; FR-16), TMF CTK in CI (NFR-09; PRD FR-8 only disclaims), v4 baseline/v5 readiness, lineage-based mapping testability against recorded responses (NFR-10), TMF637 config-only proof (AC14), TLS between services, secrets never in mappings/exports (NFR-07; FR-21 manages backend auth but export confidentiality is unstated, relevant to FR-13), one trace per call/correlation id/metrics per API-op-backend (NFR-08; PRD only has FR-16/18). Later list should name them or Out of Scope should drop them.
5. **Persona and voice shifts.** Brief personas Claire (stakeholder: "just configuration", no Java release per field move) and Marc (architect), plus consumers (ODA orchestrator, NOC, channels) reduce to Inès/Tomás. "Stateless runtime, stateful where necessary" and "instances interchangeable / horizontal scale with durable state" is replaced by "stateful runtime" (FR-5) with no scale-out/interchangeability statement; NFR-04 consistency (no lost/duplicated order on instance failure; AC12) disappears with sagas but has no placeholder. Zero Java changes to add an API is only implied by FR-1/3. Multi-tenancy and publication-reaches-all-instances are not mentioned.
