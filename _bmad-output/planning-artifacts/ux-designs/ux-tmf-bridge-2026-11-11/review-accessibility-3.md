# Accessibility review 3: Id map surface, nav and footer changes (WCAG 2.2 AA)

Scope: new Id map surface and Flow 3, the Declare backend legacy OpenAPI addition, the "Id map" nav link and "Disclaimer" footer link across all mocks. Files: EXPERIENCE.md, DESIGN.md, mockups/mock-id-map.html (4 frames), mock-backends.html, nav and footer of all mocks. Read-only; reading of source, not a rendered browser test. Items fixed in review-accessibility-2.md are not repeated.

Verdict: pass with changes. Contrast and structure of the new surface are sound; the main gaps are undefined announcement and focus behaviour for add-entry and import errors, which contradict the State Patterns announcement rule as written.

Counts: Critical 0, Major 2, Moderate 6, Low 6.

## 2. Findings

### Major

- **MA1. Add-entry error: no announcement or focus rule, and the mock cannot occur as specced (3.3.1, 3.3.3, 4.1.3, 2.4.3).** EXPERIENCE.md:146 allows exactly two cases: (a) view replaced or reloaded, focus to error heading, no `role="alert"`; (b) in place, no user action, `role="alert"`, no focus move. A clash on add is neither. In mock-id-map frame 2 the clash banner (`#e1`) has no role, no heading, no focus target, and Save is already `aria-disabled` with "off until the TMF id is not already mapped". So the error is evidently found before submit (live or on blur, a server check), yet nothing announces it: a screen-reader user typing the id hears nothing. Fix, spec both: (1) check on blur and on Save; (2) on Save with a clash, move focus to the TMF id input (`aria-invalid="true"`) and add a sentence in the case-(a) rule that for field-level errors the focus target is the first invalid field, not a heading; (3) for the on-blur check, announce through a polite `role="status"` region (one short sentence: "TMF id ORD-1 already maps to 1000234"), not `role="alert"`. Also: `aria-describedby="e1"` points at the whole banner (what, likely meaning, try, who to ask, about 60 words) so every focus on the input reads it all. Point `aria-describedby` at the one-line "what happened" sentence (its own id) and keep the rest as the visible banner. Add "Error:" or the error icon's text alternative inside that sentence so the input description is not just a statement.
- **MA2. Import rejected banner contradicts the announcement rule (4.1.3, 2.4.3).** mock-id-map frame 3: `role="alert"` on a banner that appears after the user chose a file and activated Import. That is a user action producing the error, i.e. case (a) at EXPERIENCE.md:146 (focus to heading, no alert), and the rule says "Never both". The banner also has no heading (`<b>`, not an `h2` with `tabindex="-1"` in a labelled region) and `role="alert"` would read the whole list and `dl` at once (could be dozens of rows). Fix: remove `role="alert"`; make "Import rejected. Nothing changed." an `h2` (`tabindex="-1"`) in a region labelled "Import result", move focus to it; keep the list after it as a real `ul`. State the same for success: "Imported {n} entries." (EXPERIENCE.md:187 has no announcement) should be `role="status"` with focus left on the Import button. Cap the displayed problems (for example the first 20 with "and N more", plus a downloadable list) and say so, because "each problem" for a large file defeats readability (3.3.3).

### Moderate

- **MO1. 3.3.3 suggestion that cannot be followed.** EXPERIENCE.md:185 "Try: edit that entry instead", but the Id map offers only view, add, import (IA row, line 52) and the same row says entries are never overwritten. The mock rewrote the line to "Use a different TMF id, or leave the entry as it is", so the spine and mock disagree. Pick one and align (the mock text is the correct one unless editing is added).
- **MO2. Sortable headers: announcement not specified (4.1.2, 4.1.3).** Structure in the mock is right: `th scope="col" aria-sort` containing a `button`. Gaps: (a) activating the button changes order silently; `aria-sort` is announced when navigating by cell, not on activation. Add a polite `role="status"` line ("Sorted by TMF id, ascending") and keep focus on the button. (b) The static `<caption class="sr">` says "Sorted by resource, ascending" and will go stale; drop the sort wording from the caption and rely on `aria-sort`. (c) The `▲` glyph is read as "black up-pointing triangle"; put it in `aria-hidden="true"` and use a visible indicator on every sortable column (a neutral glyph on unsorted) so sortability is discoverable (DESIGN has no sort-header component; add it: states none, ascending, descending, with the `aria-sort` mapping and the glyph being decorative). (d) Only the sorted column carries `aria-sort`, which is correct; do not add `none` to the others. (e) State the tie-break rule (stable, then TMF id) so repeated sort does not reorder equal rows unpredictably. EXPERIENCE.md:60 and Flow 3 step 2 only say "sortable like other lists". Cross-check: the Mappings list mock should use the same component.
- **MO3. Add-entry form: required fields and surface not defined (3.3.2, 1.3.5, 2.4.6).** EXPERIENCE.md:184 says the three fields are required but the mock labels carry no required marker and no `aria-required`/`required`. Add visible "(required)" text in each label (not colour or asterisk alone). The frame also has no `h1` and no stated container: is it a dialog, an inline panel above the table, or a page? Specify: if inline, `h2` "Add an entry", focus moves to the first field on open and returns to the "Add an entry" button on Cancel or Save; if a dialog, the Backends delete-dialog pattern applies (focus trap, Escape, focus return). The current mock is a card under `main` with an `h2` and no `h1` (frame 2 has none).
- **MO4. Flow 3 gaps (3.3.7, 2.4.3).** (a) Step 1 says she "picks the resource" first, but the resource is a field in the add form and the table lists all resources; reorder or add a filter control (and spec it with a label). (b) Step 4 "she returns to Test, sub-step 3": no route is given and the Id map link in the top bar leaves the mapping workspace. State that opening Id map from inside a mapping keeps the draft, step and selection (as the session-restore row does at line 219) and offer a "Back to mapping" link, otherwise redundant entry (3.3.7) and lost place follow. (c) The Exchange-view Id-map tile "Missing key" could link to the Id map surface (with the TMF id prefilled in the add form); currently it only jumps to the mapping row (see review 2 MO3).
- **MO5. Nav current-page marking: semantics right, visual and consistency gaps (1.4.1, 3.2.3).** mock-id-map and mock-backends set `aria-current="page"` on their own link: good. Problems: (a) neither DESIGN.md nor the mocks style the current link (`a` is the same colour, no bar or weight), so sighted users get no cue; add a nav-current style that is not colour-only (for example `font-weight:700` plus a 3px `primary` underline, never the focus ring shape; the stepper rule at DESIGN.md:396 is the precedent). (b) `mock-help-panel.html:83` marks Backends as current on a mapping-workspace page (crumb is "Product orders lookup"); remove it. (c) Spine nav states in EXPERIENCE.md:108 do not mention `aria-current`; add it. (d) The brand is a `<b>`, not a link, while line 108 says "Logo and home"; if it is the home link, make it one (also lets Mappings list be the "current" home).
- **MO6. Legacy OpenAPI upload control is not shown or specified (2.5.7, 3.3.1, 4.1.2, 1.3.1).** In mock-backends the Declare step only shows a read-only `dd` with a filename (`legacy-oms-openapi.yaml`); there is no file control in the "Add a backend" form and no `input type="file"`. EXPERIENCE.md:164 defines the invalid-file error but not the control. Specify: a native file input labelled "Legacy OpenAPI file (optional)" with a visible Choose button; any drag-drop zone must have the button as an equal alternative (2.5.7); chosen filename shown as text and announced via `role="status"`; "Remove file" and "Replace file" as buttons; accepted types and size stated in the helper text, linked with `aria-describedby`; on invalid file apply the same field-error pattern as MA1 (focus to the file input, `aria-invalid`). Also show the "Invalid OpenAPI upload" state in the mock.

### Low

- **L1. Invalid input state is hue-only at the border.** `border-color: var(--err)` at the same 1px weight as the valid state, the 1.95 ratio between the two borders is below 3:1 so the border alone is not a state change indicator. Text banner plus `aria-invalid` carry it, so it passes; add 2px border or an inline icon in DESIGN.md `field-input` error state to avoid relying on the banner position.
- **L2. Uppercase sort headers.** `text-transform:uppercase` on `th` and the sort buttons (mock line `th{...}` and inline style) still contradicts DESIGN.md:364 (labels render as written), already noted for tiles in review 2 L1; the Id map table adds more instances plus `sec-h`.
- **L3. Sort buttons have no visible affordance when unsorted and no size spec.** `.rowsel` is `min-height:24px`, passes 2.5.8, but the hit area is the text only. Make the button fill the `th` (padding moved from `th` to the button) so the whole header cell is the target.
- **L4. Id column semantics.** Resource column is the row header and repeats "productOrder" per row. Passes. Consider grouping by resource with a `rowspan` only if it does not break the sort; not recommended. Keep as is.
- **L5. Disclaimer link opens in the same tab while User manual opens a new tab.** Consistent order across surfaces (3.2.6 holds), but mixed behaviour in the same help block is inconsistent identification of the same kind of link (3.2.4 is not triggered, no failure). Either mark both the same, or state the reason. A same-tab navigation away from a draft also relies on session restore.
- **L6. `role="note"` glossary pop and hover-only open.** Pre-existing pattern, reused for "id map"; unchanged and fine (hover, focus and click all open it, dismissable). Confirm Escape dismisses it (1.4.13) in the spec; the mock script is not part of this scope.

## 3. Checked and passing

- Footer help block (Glossary, User manual, Disclaimer, "Need a hand? Ask your integration lead.") is identical in order across all 8 mocks including login, help panel and every Id map frame: 3.2.6 passes. Disclaimer link has descriptive text.
- Top bar order Backends, Id map, Help, Dark mode, account is the same everywhere (3.2.3). Link purposes are clear (2.4.4).
- Table: native `table`, `caption`, `th scope`, row headers, scroll region with name and `tabindex="0"` (fixes from review 1 carried). Sort button inside `th` with `aria-sort` is the correct pattern (not a clickable `th`).
- Empty state: heading, explanation and two real buttons; the primary action is first in the tab order inside the card; text tip carries the meaning.
- Save disabled via `aria-disabled` with `aria-describedby` reason: keeps the control focusable and explains it (not a `disabled` attribute). Spec that activation does nothing and announces nothing extra.
- Error banner decorative icon is `aria-hidden` and the message is text: 1.4.1 met.
- Seeded-data tip ("Infrastructure provisioning can add these entries") is plain language and not colour-only.
