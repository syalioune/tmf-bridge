# Accessibility review: TMF-Bridge Studio (WCAG 2.2 AA)

Scope: DESIGN.md, EXPERIENCE.md, .working/mock-{login,home-mappings,map-request,exchange-view,apply-summary}.html. Read-only on spines and mocks. Wiring layer treated as aria-hidden; table as truth.

Counts: Critical 0, Major 7, Moderate 10, Low 9.

## Contrast (computed in Python on actual hex values)

All text and UI pairs pass in light and dark. Lowest text ratios: muted/bg 6.56 (L), muted on warn-bg dark 5.34, primary on info-bg 5.06 (L). on-primary/primary 5.93 (L), 8.42 (D). Status pairs 5.7 to 7.96. input-border vs surface/bg/raised: L 3.88/3.49/3.68, D 3.80/4.09/3.46 (all >=3). Border token 1.38 to 1.54 is decorative only, as documented; verify nothing essential relies on it (pill `p-mut` border and card edges are not sole identifiers). DESIGN.md focus-ring claims confirmed: L 5.35 bg / 5.93 surface, D 8.72 / 8.10. No contrast defects found.

## Focus ring #1C6A94 / #5CB8E8 on filled primary buttons

- Fill and ring are the same colour (1:1), but the ring is 3px with a 2px offset, so the page background shows between button and ring. The ring is therefore distinguishable by the gap, and the ring vs the adjacent unfocused colour (surface 5.93, bg 5.35, info-bg 5.06, warn-bg 5.29; dark 6.13 to 8.72) clears 3:1. 2.4.7 and 2.4.11 pass for standalone buttons. 2.4.13 is AAA in WCAG 2.2 (not AA): thickness (3px) and contrast change pass.
- Caveats: (a) the gap is the only separator, so any ancestor that clips it breaks the ring (finding M5); (b) the same hue is used for selection (`tr.sel` bar, stepper `.cur` 2px outline), so the stepper current pill looks like a permanently focused element; (c) outline radius following needs evergreen browsers (fine for stated support); (d) forced-colors mode untested (L8).
- Recommendation: keep the 3px/2px ring, and add a 1px inner contrasting halo (`box-shadow: 0 0 0 2px var(--surface)` between fill and ring is already effectively the gap; make the gap background-independent with `outline-offset:2px` plus `box-shadow:0 0 0 2px var(--surface)`) so the ring still reads when the button sits on a tinted or primary-adjacent background. Change stepper `.cur` outline to a non-ring cue (bold text plus filled marker, 2px bottom bar).

## Major

- M1. EXPERIENCE Responsive & Platform / DESIGN Layout. 1.4.10 Reflow, 1.4.4 Resize Text. Spec fixes min width 1280, says "no responsive reflow", yet DESIGN says "usable at 200% zoom". 200% zoom on a 1280px display is a 640 CSS px viewport and 400% is 320 px, so the product fails reflow by design. The three docs also disagree on breakpoints (EXPERIENCE 1280 collapse to icons; DESIGN ~900 stack; mock 1000 stack; inspector 280px in DESIGN vs 340px in mocks). Fix: require reflow to 320 CSS px for everything except the data table (which may scroll in its own region); inspector and Help panel become stacked or a dialog/disclosure below a single breakpoint.
- M2. EXPERIENCE Interaction Primitives, Keyboard. 2.1.4 Character Key Shortcuts. `C` (Connect) and `?` (help) are single-character shortcuts, marked ASSUMPTION. Fix: active only when the table row/field has focus, plus a way to turn off or remap; or use modifier combos. `?` must never fire inside inputs or the sample editor.
- M3. All mocks (`abbr.g title=...`), EXPERIENCE Help & Glossary. 1.4.13, 2.1.1, and contradicts the spec's own "hover-only help" ban. Glossary terms use a `title` tooltip on a non-focusable `abbr`: unreachable by keyboard, unreliable on screen readers, not dismissible or persistent. DESIGN says dotted primary underline; mock uses currentcolor. Fix: render terms as buttons or `<button aria-describedby>` disclosure popovers (focus and hover, Esc to dismiss, pointer can enter the popover), or link to the Glossary anchor.
- M4. mock-exchange-view footer vs other mocks. 3.2.6 Consistent Help (A). Exchange view replaces the footer with a sticky share bar (`div.foot`) that has Glossary only; it drops "User manual" and "Need a hand? Ask your integration lead" that sit in the same footer on every other page. mock-login also has no top-bar help links and different wording ("Need access?"). Fix: one help block in a fixed relative order on every surface, including above or below the share bar.
- M5. All mocks, `.seg{overflow:hidden}` mode switch. 2.4.7, 2.4.11. The 3px/2px focus ring on each segment button is clipped by the parent's `overflow:hidden`, and the selected segment is primary-filled with a same-hue ring. Keyboard focus is nearly invisible on the mode switch. Same risk for any control inside `table{overflow:hidden}` or `.frame{overflow:hidden}` edges. Fix: use `border-radius` on buttons with `overflow:visible`, or `:focus-visible{z-index:1; outline-offset:-3px}` inside the group; add to the DESIGN Do/Don't: no `overflow:hidden` ancestor of a focusable control without inner focus ring.
- M6. mock-map-request table; EXPERIENCE Component Patterns, Interaction Primitives. 1.3.1, 4.1.2. (a) Selected row is shown by tint and inset bar only: no `aria-selected` / `aria-current="true"` / text, so AT users can't tell which row drives the inspector. (b) First cell (`id`) is `<td>`, not `<th scope="row">`, so a row has no name. (c) "Arrow keys move rows, Enter edits" is a grid pattern: spec doesn't say whether this is `role=grid` (roving tabindex, one tab stop) or a plain table with per-row buttons; mock has per-row Edit buttons so tab order is 4+ stops per row. Fix: choose one model; announce the link text ("id to orderId, transform: none, warning") via a row-level accessible description since the SVG is hidden; select state is exposed programmatically.
- M7. mock-exchange-view `<pre aria-label="HTTP request">` and `.pre{overflow:auto}`. 2.1.1, 4.1.2. `aria-label` on a generic `pre` is not exposed (naming prohibited on role generic); long curl/HTTP lines make `pre` a scrollable region with no keyboard access. Fix: `<pre tabindex="0" role="region" aria-labelledby=...>` or wrap in `<figure>` with `<figcaption>`; masked values need visually hidden text ("masked"), not `aria-label` on a span.

## Moderate

- Mo1. EXPERIENCE Accessibility Floor, all mocks. 2.4.1 Bypass Blocks: no skip link or "skip to main / skip to table" specified. Landmarks in mocks are good (header, nav labelled, main, aside labelled "Inspector", footer), but the Exchange view's share bar is a bare `div` (no `role=region` with name) and multiple `main` appear only because mocks stack frames. Add skip links: main, inspector, share bar.
- Mo2. Mocks (titles) and Accessibility Floor. 2.4.2, 2.4.6, 1.3.1: `<title>` is "Map request mock" etc.; spec doesn't define per-step document titles or route-change announcement. Heading structure: Exchange panels 1 and 2 are `<b>` in `<summary>` while panel 3 is `<h2>`; Apply-done state has no `h1` (only `h2 "What next"`); Map request has no `h2` in main. "Focus lands on the step heading" needs `h1 tabindex="-1"`. Spec "Step {n} of 6, {name}" announcement should be a polite live region plus focus, not both.
- Mo3. Mocks, row buttons. 2.4.6 / 2.5.3 context: every row has the same "Edit", "Open", "Export" names; the Mappings list repeats "Open" next to a name link that already opens the mapping. Add `aria-label="Edit id mapping"` style names (label-in-name preserved) and drop the redundant Open button or the name link.
- Mo4. mock-exchange-view inspector "Checks that ran". 1.1.1, 1.4.1: pills contain only a glyph (✓, ✗, –) with no word; the pass/skip meaning rests on the sentence ("no", "not checked") and the glyph is read as "check mark", "multiplication x". The top pills do have words. Fix: add "Passed / Failed / Skipped" text (visible or hidden) in every checks list item; mark decorative glyphs `aria-hidden`.
- Mo5. EXPERIENCE Component Patterns (Share bar), Accessibility Floor. 2.4.11 Focus Not Obscured (min): only the sentence "sticky share bar must not cover focused elements". Specify `scroll-padding-bottom` equal to the bar height, and test with the Verdict "Go to the mapping row" jump and Tab order. At 200% zoom a sticky bar that wraps to 3 lines can cover most of the viewport; consider unsticking below a height.
- Mo6. EXPERIENCE Declare backend vs Backends surface. 3.3.7 Redundant Entry: step 2 has the analyst enter the endpoint while Backends is a separate surface that already stores endpoint + secret NAME. Make step 2 select an existing backend (with "Add new backend" inline) rather than re-typing; also do not require re-entering the sample id for the real call (Flow 3).
- Mo7. EXPERIENCE Sample editor, Invalid sample JSON. 2.1.2 No Keyboard Trap, 3.3.1: not stated whether the JSON editor is a plain `textarea` or a code editor that captures Tab. Require an Esc-then-Tab escape or no capture. Error line/column must be linked with `aria-invalid` and `aria-describedby`; Run `aria-disabled` reason also associated.
- Mo8. EXPERIENCE Side-by-side mode / lineage. 4.1.3 Status Messages, 1.1.1: live test re-runs on edit against saved sample, with no announcement policy (debounced `role=status` summary), and lineage has no text alternative defined (a graph would need a list/tree equivalent). Spec the text form.
- Mo9. EXPERIENCE State Patterns (error pattern). 4.1.3: "move focus to the message" and "`role=alert`" together double-announce; error container needs `tabindex="-1"`. Pick one: focus the heading inside a labelled region, or `role=alert` without focus move, and keep both consistent between the login, Exchange view, and inline errors.
- Mo10. DESIGN Components (Help link), mock `.q` 20x20. 2.5.8 Target Size (Minimum): 20px target relies on the spacing exception (24px circle must not touch another target). Tight clusters (header `?` beside links, stepper) may fail; change to 24px minimum. Mock small buttons at 28 to 30px pass.

## Low

- L1. Mock vs spec: Draft pill has no icon (spec: "always text + icon"); not a WCAG failure but a spec conformance gap. Stepper "todo" has no text state (number only plus position); acceptable via `aria-current`.
- L2. Mock vs spec drift: nav shows email + Sign out + Glossary + User manual; spec says Help `?`, dark-mode toggle, account menu (Sign out only). Dark-mode toggle needs a name and state (`aria-pressed` or select) once built. Help panel (dockable, search) has no mock; spec it as a non-modal complementary region with Esc behaviour consistent with M2 and Esc in inspector.
- L3. Token drift between DESIGN and mocks: input-border #7A828F vs #7B838F (L), #6B7482 vs #727A87 (D); both pass; body 16 vs 15px; h1 26 vs 22px; secondary button 2px border vs 1px; essential text below the 14px floor in mocks (12px `th`, 12px caption/url, 13px pills, chips, footer, dt). Align mocks to DESIGN (14px minimum) or relax DESIGN.
- L4. Mock disabled buttons use `disabled` (removes from tab order, no reason text) while State Patterns require `aria-disabled` with visible reason. The mock shows no example; update when mocking Run/Delete.
- L5. Links that open the external manual in a new tab: spec says "(opens in a new tab)" in the accessible name; none of the mock `?` or manual links carry it. `?` link name pattern "Help: X" is good (label-in-name for the visible "?" is by convention acceptable).
- L6. Forced colors / high contrast: selection bar uses `box-shadow` and pills use background-only tint; both vanish in forced-colors. Add `@media (forced-colors:active)` rules (borders, `outline`, `ButtonText`) and test the wiring SVG strokes use `currentColor`.
- L7. Toast ("Saved.", "Copied."): no min duration or pause; auto-dismiss with no recovery would hit 2.2.1; skeleton shimmer needs reduced-motion variant (mock global `animation:none` is good).
- L8. Stepper in mock is a plain `ol` of non-interactive `li`s, but spec says completed steps are reachable and revisit in any order: when built they must be buttons/links with `aria-current="step"`; `overflow:auto` on a narrow stepper creates an unfocusable scroll region (add `tabindex=0` or wrap). Current-step style (2px primary outline) mimics the focus ring.
- L9. Drag-and-drop 2.5.7: satisfied by Connect picker + table editing. Gaps: field lists (source of drags) are not in any mock, the Connect button in the mock is a generic toolbar action rather than bound to the selected row, and the picker's control type (searchable listbox/combobox, `aria-activedescendant`, labelled, Esc closes) is not specified. The tip text calls a button `<kbd>`: use plain button text.

## Passes worth keeping

- 3.3.8 Accessible Authentication: OIDC redirect, no typing, no cognitive test (mock-login).
- Colour: status = icon + text; dashed warnings; contrast all pass in both themes.
- `html lang`, labelled `nav`, labelled `aside`, `th scope=col`, table `caption`, `aria-current="step"`, hidden step "(done)" text, `role=alert` on errors, `role=status` on pass/warn, reduced-motion global rule.
- Plain-language, non-blaming error pattern; confirm dialog default focus on safe action; focus return to trigger.
- 3.2.6 aside from M4: help links sit in the same header/footer positions on 4 of 5 mocks.
